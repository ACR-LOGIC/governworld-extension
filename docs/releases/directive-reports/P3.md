# Task Report — P3: Incremental Scan Result Sync to Popup & Badge

## 1. Task ID and title
**P3** — Popup and badge counts go stale (emit updated `SCAN_RESULT` after every incremental rescan, option (a)).

## 2. What changed
- **Before:** Incremental DOM rescans in `src/content/content.ts` updated on-page overlay masks locally inside `rescanAffectedRegions()`, but never sent an updated `SCAN_RESULT` to the service worker. Even if one had arrived after the initial `POPUP_SCAN`, `handleContentScanResult()` in `src/service-worker/index.ts` dropped any `SCAN_RESULT` once `pendingScans.get(tabId)` was empty. In Chrome 159 Run 2, `0/5` trials reflected incremental findings in the service-worker session, action badge, or popup UI.
- **After:** Implemented option (a):
  - In `src/content/content.ts`, preserved initial scan metadata (`lastAttrChars`, `lastTruncated`, `lastCoverageStatus`, `lastDeferredMediaCount`, reset in `clearSession()`), factored `emitScanResult(requestId, extraStats)`, and invoked `emitScanResult(\`rescan_\${Date.now()}\`)` at the end of `rescanAffectedRegions()`.
  - In `src/service-worker/index.ts`, updated `handleContentScanResult()` so when `pendingScans` has no entry for `tabId`, an incremental `SCAN_RESULT` whose `sessionId` matches `readSession(tabId)` updates the stored session (preserving prior `imageCandidates` metadata), pushes `POPUP_STATE` via `notifyPopup()`, and updates the tab action badge via `updateBadgeForTab(tabId, findings.length)`. Stale/mismatched `sessionId` messages remain dropped fail-closed.

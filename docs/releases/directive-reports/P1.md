# Task Report — P1: Fix `characterData` Mutation Blind Spot

## 1. Task ID and title
**P1** — `characterData` blind spot (re-extract and re-detect mutated `Text` nodes in `rescanAffectedRegions`, option (a)).

## 2. What changed
- **Before:** When a `Text` node was edited in place (`MutationRecord.type === "characterData"`), `rescanAffectedRegions()` in `src/content/content.ts` removed old findings and spliced the node's segment out of `combined`, then ran detection **only** on `batch.addedNodes`. In-place edits introducing new secrets (e.g., an SSN typed or mutated into an existing text node) were never re-extracted, detected, or masked (`0/5` in live Chrome). Additionally, `clearSession()` did not cancel/clear `pendingMutationBatch`, and `startMutationObserver()` overwrote `pendingMutationBatch` instead of merging coalesced batches.
- **After:** Implemented option (a):
  - `extractVisibleText()` in `src/content/extract.ts` now accepts `Text` nodes cleanly in its TypeScript signature alongside `Document | Element | ShadowRoot`.
  - `rescanAffectedRegions()` in `src/content/content.ts` executes whenever `mutatedTextNodes.length > 0`, records and rebases surviving DOM findings' combined offsets when spliced segments change indices, merges coalesced batches in `startMutationObserver()`, resets pending mutation state in `clearSession()`, drops stale rects on disconnected nodes in `getOverlayItems()`, and calls a shared `appendAndDetectNode()` helper (with `enrichAndBoostNames` for `possible_name` matches) for both connected `batch.addedNodes` and deduplicated connected `batch.mutatedTextNodes` not already covered by an added ancestor. When 0 selected findings remain after an edit, `overlay?.clear()` clears stale overlay rectangles.

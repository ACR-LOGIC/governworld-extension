# Task Report — P7: Adaptive Mutation Debounce for Sub-250ms Single-Node Masking

## 1. Task ID and title
**P7** — Incremental latency floor of 650 ms or more (adaptive debounce for small batches `<= 10` nodes while keeping 500 ms burst coalescing, option (a)).

## 2. What changed
- **Before:** Every DOM mutation waited through a fixed `150 ms` `MutationObserver` debounce in `src/content/normalization/mutation.ts` stacked on top of a fixed `500 ms` rescan timer in `src/content/content.ts`, creating a hard `>= 650 ms` floor (`p50 679.2 ms` after P1) even for single-node edits whose actual detection takes `~0.04 ms`. Creating `[data-gw-scan-overlay]` on `document.body` also emitted a childList mutation back into the observer.
- **After:** Implemented option (a):
  - In `src/content/normalization/mutation.ts`, exported `SMALL_BATCH_NODE_THRESHOLD = 10`, `FAST_DEBOUNCE_MS = 16`, `BURST_DEBOUNCE_MS = 150`, and `selectObserverDebounceMs(batchSize)`. `scheduleFlush()` uses `16 ms` when `batchSize <= 10` and retains `150 ms` for bursts `> 10` nodes.
  - In `src/content/content.ts`, `startMutationObserver()` filters out GovernWorld internal UI elements (`isInternalUiNode`: `[data-gw-scan-overlay]`, `[data-gw-toast-host]`, `[id^='__governworld-']`) so painting overlay masks never triggers a self-rescan cycle, and schedules `rescanAffectedRegions` at `SMALL_BATCH_RESCAN_DELAY_MS = 20 ms` when accumulated batch size `<= 10`, while preserving `BURST_RESCAN_DELAY_MS = 500 ms` when batch size `> 10`.

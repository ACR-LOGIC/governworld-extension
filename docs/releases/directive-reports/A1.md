# S6 Task Report — Task A1: Auto-Mask Single Names Checkbox (Decision D1, Default OFF)

**Task A1 — Auto-mask single names checkbox, default OFF (Decision D1)**

## 2. What changed — behaviour before and after, in plain language
- **Before:** `src/content/content.ts` auto-selected only structured multi-part names (`selected: match.category !== "possible_name" || isNameStructured(parsedName)`), leaving single-token names unchecked (`selected: false`) for manual review without a user setting to opt into auto-masking single names. In addition, `detectNames` in `src/content/detectors/names.ts` only matched single-token labeled names if they carried an honorific or non-ASCII diacritic.
- **After:**
  1. **Labeled single-name detection (`src/content/detectors/names.ts`):** Any single capitalized name token following an explicit name label (`NAME_LABEL_RE`, such as `Patient: Maria`) that is not in `GENERIC_NAME_LABELS` is detected as a `possible_name` finding at `confidence = 0.52`.
  2. **`autoMaskSingleNames` setting (`src/shared/settings.ts`, `src/shared/policyOwnership.ts`, `src/shared/types.ts`, `src/shared/messages.ts`, `src/service-worker/index.ts`, `src/content/content.ts`):** Added `autoMaskSingleNames: boolean` (default `false` in `DEFAULT_SETTINGS`). When `false`, single-token names remain detected and unchecked (`selected: false`) in Review while structured multi-part names auto-select (`selected: true`). When `true`, single-token `possible_name` findings are auto-selected (`selected: true`) and masked with the rest.
  3. **Frontend toggle in Settings → Detection (`src/popup/index.html`, `src/popup/popup.ts`, `src/shared/i18n.ts`, `src/sidepanel/sidepanel.html`):** Added `#auto-mask-single-names-toggle` (`Auto-mask single names (Possible name)`) and help text `#auto-mask-single-names-desc` (`Default off: single names remain review-only (unchecked) to avoid false positives, while multi-part structured names still auto-mask.`) across all 7 UI languages (`en`, `es`, `fr`, `de`, `ja`, `pt`, `zh`).

# Task Report — P5: Unicode Email Exact-Span Detection

## 1. Task ID and title
**P5** — Unicode email exact-span miss (`EMAIL_RE`, `detectEmails`, `maskValue`, and `isMaskedPreview` Unicode support, option (a)).

## 2. What changed
- **Before:** `EMAIL_RE` in `src/content/detect.ts` used ASCII-only `\b` and `[A-Za-z0-9...]` character classes, and `detectEmails()` checked `/[A-Za-z]/`. On `"josé.maría@example.test"`, regex matching skipped `josé.mar` because `\b` fails at `é`/`í`, matching only `"a@example.test"` (`[31, 45)`) and reducing strict Run 1 exact-span recall to `21/22` (`95.5%`). Additionally, `maskValue("email", ...)` indexed `local[0]` without code-point slicing and `isMaskedPreview("email", ...)` in `src/shared/messages.ts` rejected previews beginning with accented characters (e.g. `é***@klinik.example.de`).
- **After:** Implemented option (a) (Unicode-aware matching with **no** accent stripping or normalization before matching):
  - Updated `EMAIL_RE` in `src/content/detect.ts` to use negative Unicode lookbehind `(?<![\p{L}\p{N}.!#$%&'*+/=?^_`{|}~-])` and `[\p{L}\p{N}...]` character classes with the `/gu` flag.
  - Updated `detectEmails()` to check `/\p{L}/u.test(value)`.
  - Updated `maskValue("email", ...)` to use `Array.from(local)[0] ?? ""` so multi-byte/non-BMP leading characters are preserved safely without splitting surrogate pairs.
  - Updated `isMaskedPreview("email", ...)` in `src/shared/messages.ts` to accept Unicode letter/number characters (`/^(?:[\p{L}\p{N}._%+-]{0,2}\*{3,}@[\p{L}\p{N}.-]{1,190}|[\s*]+)$/u`).

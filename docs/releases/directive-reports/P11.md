# Task Report — P11: Single Version Source of Truth & CI Parity Check

## 1. Task ID and title
**P11** — Version strings out of sync (`package.json` as single source of truth `0.4.1`, synced to all manifests/constants/docs/UI and enforced as a CI hard failure).

## 2. What changed
- **Before:** Version strings existed independently in `package.json`, `package-lock.json`, `manifest.json`, `manifest.firefox.json`, `src/api/config.ts`, `src/landing/index.html`, `src/popup/privacy.html`, `README.md`, and `AGENTS.md` (all at `0.4.0` while git tag `v0.4.1` diverged), no sync generator script existed in `package.json` or CI workflows, and **Settings → About & Diagnostics** displayed no extension version row.
- **After:**
  - Set `"version": "0.4.1"` in `package.json` as the single source of truth.
  - Created `scripts/sync-version.mjs` supporting `--write` (`npm run sync:version`) and `--check` (`npm run sync:version:check`) to keep `package-lock.json`, `manifest.json`, `manifest.firefox.json`, `src/api/config.ts` (`CURRENT_EXTENSION_VERSION`), `src/landing/index.html`, `src/popup/privacy.html`, `README.md`, and `AGENTS.md` synchronized with `package.json`.
  - Added `#diag-version-value` (`diag_version` translated key in all 7 locales) inside **Settings → About & Diagnostics** (`src/popup/index.html`, `src/sidepanel/sidepanel.html`, `src/popup/popup.ts`), populated dynamically from `chrome.runtime.getManifest()?.version || CURRENT_EXTENSION_VERSION`.
  - Extended `tests/version-parity.test.ts` to assert parity across all manifests, constants, lockfile, `README.md`, `AGENTS.md`, `privacy.html`, `landing/index.html`, popup/sidepanel UI markup, and `sync-version.mjs --check`.
  - Wired `npm run sync:version:check` into both `.github/workflows/ci.yml` and `.github/workflows/release.yml` as a blocking failure check.

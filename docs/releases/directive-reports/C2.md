## 1. Task ID and title

**C2** — Startup purge and retention audit for staged documents

## 2. What changed — behaviour before and after

- **Before:** While Task `P4` added prefix deletion on `Cancel` / `Start Over` and `purgeOrphanedStagedKeys()` on service-worker startup, Document Studio had no UI showing how much staged data (keys and bytes) was currently stored in IndexedDB (`governworld-redaction` / `docfiles`), no distinction between active live-session data and orphaned data in the UI, and no user-facing button to purge staged data with confirmation.
- **After:**
  - **Backend (`src/service-worker/documents.ts`, `src/service-worker/index.ts`, `src/shared/types.ts`, `src/shared/messages.ts`):** Added `collectLiveStagedRoots()`, `getStagedStorageAudit()` (returning `{ totalKeys, totalBytes, liveKeys, liveBytes, orphanKeys, orphanBytes, hasInFlightJob }`), and `purgeStagedData({ includeIdleSession })` (returning `{ deletedKeys, deletedBytes, preservedLiveSession, remaining }`), wired to validated messages `POPUP_GET_STAGED_STATS`, `POPUP_PURGE_STAGED_DATA`, and `POPUP_STAGED_STATS_STATE`. Confirmed `purgeOrphanedStagedKeys()` runs automatically at service-worker boot and `chrome.runtime.onStartup`, deleting orphaned prefixes while preserving live sessions (`sessions`, `inFlightFileKeys`, `lastDocSession`, and active staged marker).
  - **Frontend (`src/popup/index.html`, `src/popup/popup.css`, `src/popup/popup.ts`, `src/shared/i18n.ts` across all 7 locales + synced `src/sidepanel/sidepanel.html` & `sidepanel.css`):** Added the Document Studio staged-storage audit bar (`#doc-staged-audit`) displaying exact stored key count, formatted byte size, and live-session vs. orphaned breakdown (`#doc-staged-summary`), a **"Purge staged data"** button (`#doc-purge-staged-btn`) with inline confirmation (`#doc-purge-confirm-bar`: `#doc-purge-confirm-yes` / `#doc-purge-confirm-no`), and a polite status confirmation message (`#doc-staged-confirm-msg`).

# GovernWorld Redaction — Enterprise Deployment & Policy Guide

GovernWorld supports centralized enterprise policy management via `chrome.storage.managed` (`schema/policy.json`).

This guide details how enterprise administrators deploy, configure, and enforce data protection across Chromium-based managed browsers (Google Chrome, Microsoft Edge, Brave) and Firefox.

---

## 1. Core Enterprise Features

* **Fail-Closed Policy Resolution:** If an enterprise policy is detected but is malformed, GovernWorld locks the interface into maximum protection rather than falling open to consumer control.
* **Mandated Categories:** Administrators mandate specific PII/PHI categories (e.g. SSN, credit cards, medical record numbers). Mandated categories are merged with user settings and cannot be deselected by end users.
* **Locked Protection Modes:** Force `always-on` or `this-tab` protection mode; disallow users from turning protection off.
* **Zero Cloud Egress:** All detection, visual masking, and document redaction run client-side on-device with zero telemetry or unmasked egress.

---

## 2. Policy Schema Reference (`schema/policy.json`)

| Property | Type | Default | Description |
|---|---|---|---|
| `protectionMode` | `string` (`"off"`, `"this-tab"`, `"always-on"`) | `"this-tab"` | Enforced paste and visual protection coverage. |
| `userCanDisable` | `boolean` | `false` | When `false`, user cannot change mode or remove mandated categories. |
| `enforcedCategories` | `array` of strings | `[]` | Categories that must remain permanently active. |

Supported category identifiers:
`email`, `phone`, `ssn`, `dob`, `medical_record_number`, `member_id`, `npi`, `dea`, `mbi`, `address`, `payment_card`, `secrets`, `possible_name`, `custom`, `canadian_sin`, `uk_nhs`, `aadhaar`, `pan_india`, `australian_tfn`, `cpf`.

## 3. Deployment Examples

### A. Windows (Group Policy / Registry)

Registry Key:
`HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Google\Chrome\3rdparty\extensions\<EXTENSION_ID>\policy`

Registry Values (REG_SZ / REG_DWORD / JSON string):
```reg
Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Google\Chrome\3rdparty\extensions\<EXTENSION_ID>\policy]
"protectionMode"="always-on"
"userCanDisable"=dword:00000000
"enforcedCategories"="[\"ssn\", \"payment_card\", \"secrets\", \"medical_record_number\", \"npi\"]"
```

### B. macOS (Configuration Profile / MDM)

Payload under `com.google.Chrome.extensions.<EXTENSION_ID>`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>protectionMode</key>
  <string>always-on</string>
  <key>userCanDisable</key>
  <false/>
  <key>enforcedCategories</key>
  <array>
    <string>ssn</string>
    <string>payment_card</string>
    <string>secrets</string>
    <string>medical_record_number</string>
  </array>
</dict>
</plist>
```

### C. Linux (Managed Policy File)

Create `/etc/opt/chrome/policies/managed/governworld_policy.json`:

```json
{
  "3rdparty": {
    "extensions": {
      "<EXTENSION_ID>": {
        "protectionMode": "always-on",
        "userCanDisable": false,
        "enforcedCategories": [
          "ssn",
          "payment_card",
          "secrets",
          "medical_record_number",
          "npi"
        ]
      }
    }
  }
}
```

## 4. Force-Installing via Google Admin Console

1. Navigate to **Devices > Chrome > Apps & extensions > Users & browsers**.
2. Select target Organizational Unit (OU).
3. Add GovernWorld Redaction by extension ID.
4. Set installation policy to **Force install** or **Force install + pin to browser toolbar**.
5. In **Policy for extensions**, paste the JSON configuration:

```json
{
  "protectionMode": "always-on",
  "userCanDisable": false,
  "enforcedCategories": [
    "ssn",
    "payment_card",
    "secrets",
    "medical_record_number",
    "npi",
    "dea",
    "mbi"
  ]
}
```

## 5. Enterprise Audit Verification

Audit events generated by GovernWorld are signed with a non-extractable ECDSA P-256 key and cryptographically hash-chained using SHA-256.

To verify audit exports submitted by workstations:

```bash
node scripts/verify-audit.mjs /path/to/employee-audit-export.json
```

Output:
```
Verifying audit export: employee-audit-export.json
PASS: ECDSA P-256 digital signature verified.
PASS: Hash chain verified intact across 42 events.
VERIFICATION SUCCESSFUL: Audit log is authentic and untampered.
```
